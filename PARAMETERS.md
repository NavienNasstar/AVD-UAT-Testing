# AVD session hosts: parameters

Shared Practice code. It holds **no customer values and no `.bicepparam` files**. The customer's pipeline reads the
customer's Azure DevOps variable library and passes the values as inline parameters (`-p name=value`).

Files: `vms.bicep` (entry, subscription scope) and `vm.bicep` (one VM, called by `vms.bicep`). Both compile with no warnings (Bicep CLI 0.48.1).

## 1. Required: 11 values per customer

| Parameter | Example | Source |
|---|---|---|
| `avdSubscriptionID` | `cf5274f9-...` | Library |
| `primaryRegion` | `uksouth` | Library |
| `primaryRegionSH` | `uks` | Library |
| `companyPrefix` | `nas` | Library. Drives most names. |
| `env` | `uat` / `prod` | Fixed by the pipeline file |
| `vmSku` | `Standard_E8ds_v5` | Library |
| `joinType` | `domain` / `entra` / `none` | Library |
| `hostDeployCount` | `3` | Run dialog |
| `currentHostCount` | `0` | Run dialog |
| `imageReference` | `.../versions/latest` | Run dialog |
| `hostpoolToken` | (secret) | Generated by the pipeline |

## 2. Optional: derived from the customer abbreviation (set a library variable only to override)

| Parameter | Default (example for `nas`, `uks`, `prod`) |
|---|---|
| `workload` | `general` |
| `sharedInfraEnv` | `prod` (UAT and PROD share vnet, key vault, DCR, resource group) |
| `resourceGroupName` | `rg-nas-uks-avd-prod` |
| `hostpoolName` | `hp-nas-uks-prod` (`-uat` for UAT) |
| `vnetName` / `subnetName` | `vnet-nas-uks-avd-prod` / `snet-nas-uks-avd-prod` |
| `vnetRgName`, `vnetSubscription` | the VM resource group, the VM subscription |
| `keyvaultName` / `keyvaultRgName` | `kv-nas-uks-idty-prod` / `rg-nas-uks-identity-prod` |
| `keyvaultSubscription` | the VM subscription |
| `adminUsernameSecretName`, `adminPasswordSecretName` | `adminUsernameSecret`, `adminPasswordSecret` |
| `domainPasswordSecretName` | the admin password secret name (only used for domain join) |
| `computerNameStem` | `NASAVDUKS-` (PROD), `NASAVDUKS-U` (UAT). 15-character limit enforced. |
| `availabilityZones` | `[1, 2, 3]`: VMs are spread over the zones. Empty array = no zone. |
| `dcrName` / `dcrRG` / `dcrSub` | `MSVMI-nas-win-dcr-prod` / `rg-nas-uks-logging-prod` / the VM subscription |
| `domainName`, `ouPath`, `domainUsername` | only needed when `joinType` is `domain` |

## 3. Optional features (defaults set by Practice standards)

`trustedLaunch` (default true), `encryptionAtHost` (false), `enableAma` (false), `enableGuestConfig` (false), `enableDefender` (false).

## 4. Fixed standards (hard-coded in `vm.bicep`, not parameters)

OS disk 128 GB `Premium_LRS`, delete option *Delete* for VM, NIC and disk, system-assigned identity, automatic updates on,
AVD agent DSC URL, host pool registration extension, tags `Workload` and `Env`.

## Minimal example

```bash
az deployment sub create --name vms-<build>-prod --location uksouth \
  --template-file vms.bicep --parameters \
  avdSubscriptionID="<sub>" primaryRegion=uksouth primaryRegionSH=uks companyPrefix=nas env=prod \
  vmSku=Standard_E8ds_v5 joinType=entra hostDeployCount=3 currentHostCount=0 \
  imageReference="<image version id>" hostpoolToken="<token>"
```

## Renamed or removed compared with the earlier version

- `adminUsernameSecret`, `adminPasswordSecret`, `domainPasswordSecret` are now `...SecretName` (the Bicep linter flags names containing "secret" unless they are `@secure`; these are names, not values).
- `osDiskSizeGB`, `osDiskStorageAccountType`, `avdAgentModulesUrl` are fixed standards, no longer parameters.
- `zone` (one number) is replaced by `availabilityZones` (a list).
- The computer name stem (including the UAT `U`) is now worked out inside the Bicep, so the pipeline no longer needs the stem code.

## Azure Update Manager (optional)
| Parameter | Default | Meaning |
|---|---|---|
| patchMode | AutomaticByOS | Set `AutomaticByPlatform` so Azure Update Manager (and your maintenance configuration) patches the VM |
| assessmentMode | ImageDefault | Set `AutomaticByPlatform` for a daily update assessment |
| maintenanceConfigurationId | (empty) | Full resource ID of a maintenance configuration. When set, each new VM is assigned to it at deploy time. The pipeline identity needs Microsoft.Maintenance/configurationAssignments/write on the VM and read on the configuration. |

Set both in the customer variable group. The maintenance configuration itself (schedule, and assignment by dynamic scope or policy) is not created by this Bicep.
